# MIRACL の 0.7366、0.7116、0.7153 と再計算 0.7190

再計算（`miracl_repro/sim.py`）の 0.7190 は、接頭辞あり・タイトルなしの密ベクトル（厳密な内積）に、Sudachi と文字バイグラムを足し、k=60、深さ 64 で融合した nDCG@10 である。`sim.py` の `local-sim dense pref+sudachi+bigram k60 d64`。密だけの接頭辞ありは 0.8195、接頭辞なしは 0.8410。fastembed の sparse は 30 クエリ中 25 でヒットが 0。

どれも 512 トークンでは切っていない。こちらの索引はモデルの 8192 を読む（`kbindex/embed.py`）。再計算の `emb.py` も `max_seq_length` を 512 にしない。MIRACL の 292 文書はほぼ 512 未満で、1 文書だけ超える。この差の原因ではない。

## 0.7366

`cursor/title-k60-run-5946` の `fa88385623808e5635d46dc376a826930273ded0`。コードは `6aa48bc`。コマンドは `bench/standalone_bench.py run --subset miracl-ja-dev-s30 --kb miracl-title`。再起動は 2026-11-18T04:49:25Z、MIRACL は 2026-11-18T05:25:54Z に終了 0。`summary.json` の nDCG@10 は 0.7366108275849311。

条件は、接頭辞あり、融合 k=60、深さ `max(limit*2, 64)=64`、Sudachi と文字バイグラム、そしてレコードのタイトルを最初の本文の前に `title\n` で付けた。ハーネスがそのタイトルを送った。

0.7190 との差は +0.0175。同じ 3 本・k=60・深さ 64・接頭辞ありに対して、こちらだけタイトルを本文に足している。0.7116（タイトルなしの HTTP）との差は +0.0250 で、変えたのはタイトルだけである。タイトルがこの上振れの原因である。

## 0.7153

`bench/results/ablation/scores.json`。variant `dense+sudachi+bigram k=60`、subset `miracl-ja-dev-s30`、source `engine.search`、nDCG@10 0.7152737782491414。

生きている索引に対するプロセス内の `Engine.search` である。接頭辞あり、タイトルなし、k=60、深さ 64、3 本。密だけの同じ計測は 0.8194517719806734 で、再計算の接頭辞あり密だけ 0.8195 と小数 4 桁まで一致する。密の上位は HNSW と INT8 では動いていない。

0.7190 との差は −0.0037。密が一致しているので、残りはキーワード側である。再計算の BM25 は MIRACL 292 文書だけの IDF で、順位を全部作ってから 64 で切る。こちらのアブレーションは Postgres の BM25 で、そのとき jqara と jsquad のポスティングも同じ世代にあり、df は kb をまたぐ。候補は kb で切るが、IDF は切らない。これが 0.0037 の原因である。

## 0.7116

`BENCHMARK.md` の自前 k=60。HTTP ハーネスの nDCG@10。`bench/results/selfbuilt-k60/miracl-ja-dev-s30/summary.json`。接頭辞あり、タイトルなし、k=60、深さ 64、3 本、`maxChunksPerRecord=1`。

0.7153 との差は −0.0037。同じ索引、同じ k、同じ深さである。違いは HTTP が `maxChunksPerRecord=1` で切ってから limit 10 を返すことと、プロセス内が融合リストを直接採点したことである。`BENCHMARK.md` はこの二つを 0.004 以内と書いている。k でも深さでも接頭辞でもタイトルでもない。

0.7190 との差は −0.0074。内訳は上の二つを足したもの。−0.0037 が kb をまたぐ IDF、−0.0037 が HTTP の切り方。512 でも HNSW でもない。密だけの 0.8195 が両方で一致している。

このブランチの C（接頭辞なし、密だけ、HTTP）は nDCG@10 0.8410 で、再計算の「接頭辞なし密だけ」と小数 4 桁まで一致する。B（接頭辞なし、k=1、深さ 80、Sudachi と文字バイグラム）は 0.6977 である。これは 0.7190 とは別の条件である。0.7190 は接頭辞あり、k=60、深さ 64 である。

## 混同しない数

こちらの k=2（1 始まりで `1/(2+rank)`、0 始まりなら `1/(pos+3)`）の HTTP は 0.7283、プロセス内は 0.7319984245502975。PipesHub の式は `1/(pos+2)` で、こちらの k=1 に当たる。k=2 の計測は再計算の 0.7190 とも PipesHub の 0.8314 とも同じ融合ではない。
